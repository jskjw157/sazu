# SAZU 품질 중심 개발 단계

작성일: 2026-10-21  
상태: **하위 시스템 분할·완료 기준 제안**. 실행 가능한 코드나 테스트 통과 보고가 아니다.

상위 결정: [상용 운세 API 미사용](decisions/0001-no-commercial-fortune-api.md). 현재 상세 설계: [S1 원천·시간 기반](superpowers/specs/2026-10-21-self-hosted-foundation-design.md).

## 1. 방향

일정이나 개발공수에 맞추어 계산 근거·검증을 생략하지 않는다. 대신 변경을 검토할 수 있는 단위로 나누고, 각 단계에서 실제 증거를 남긴다. 예전 자료의 10월 25일 데모 일정과 80개 원고 수량은 현재 출시 완료 조건이 아니다.

이 로드맵은 여러 하위 시스템의 경계와 의존관계를 정한 것이며, 아직 작성하지 않은 파일별 구현 계획을 승인한 것으로 취급하지 않는다. 하위 시스템마다 상세 설계 → 구현 계획 → 실패 테스트 → 구현 → 검증 → 검토를 수행한다.

## 2. 단계와 완료 증거

| 단계 | 결과물 | 완료에 필요한 증거 | 현재 상태 |
|---|---|---|---|
| S0 방향·범위 | 상용 API 제외 결정, 하위 시스템 분할, S1 설계안 | 기존 자료 보존, 문서 정합성, 사용자 요구와 가정 구분 | 결정 기록 작성; 상세 설계 검토 전 |
| S1 원천·시간 기반 | 한국 달력 어댑터, 절기 생성/검증, 시간 정규화, 배포본 manifest | 원천 권리/해시, 독립 대조, gap/fold·정밀도·재현 시험, 실패 차단 | 상세 설계안 작성; 코드 미구현 |
| S2 사주 계산 핵심 | 연·월·일·시주, 육십갑자, 오행 단순분포, 명명된 규칙 | 관례별 경계 기대값, 실제 전환 전후, 불확실 구간·trace, 변경 비교 | 미설계/미구현 |
| S3 저장·자체 API | PostgreSQL migrations, 불변 차트, 자체 계산 API, 문서화된 계약 | 빈 DB/기존 DB migration, 중복·충돌·동시성, 버전 혼합 차단, API 계약 시험 | 미설계/미구현 |
| S4 근거형 해석 | 특징 사전, 원고 승인, 조건 평가, 근거 trace, 표현 검증 | true/false/unknown, 공집합, 중복/충돌, 미승인 원고 차단, 없는 값 생성 차단 | 기존 초안만 존재 |
| S5 사용자 경험 | 모바일 설정·결과·대화·캐릭터·동의한 기억 | 사용자 격리, 삭제/동의 철회, 파트너 일관성, E2E·접근성·위기 대응 | 기존 기획 자료만 존재 |
| S6 심화 규칙 | 대운·세운·궁합·지장간·강약·용신·격국의 개별 모듈 | 문헌/관례 출처, 비교 가능한 규칙 프로필, 계산과 해석 점수 구분, 각 모듈 회귀시험 | 개별 설계 필요 |
| S7 출시·운영 검증 | 보안·성능·백업/복원·관측·릴리스/롤백·운영 매뉴얼 | 외부 의존성 차단, 권한·오용 시험, 복구 실측, 공급망·라이선스 검토, 알려진 한계 | 미실행 |

S6는 기능 묶음을 한번에 만들어 완료 처리하지 않는다. 대운, 관계 비교, 용신 등은 각각 좁은 설계·검증 단위로 분할한다. S7의 기초 보안/관측은 앞 단계부터 적용하고 최종 단계에서 통합 검증한다. 보안 작업을 마지막까지 미룬다는 뜻이 아니다.

## 3. 우선 구현 대상: S1

S1을 다음 세 부분으로 구분한다.

### S1-A: 자료 계약·한국 달력

원천 manifest, 지원범위, 엄격한 달력 입력, 윤달 미상, 라이브러리 실패 상태 격리, 한국 양음력 왕복과 공식 값 대조 경로를 만든다. 상용 API 클라이언트나 사용자 계정 기능은 넣지 않는다.

**핵심 완료 증거:** 무효 입력에서 이전 결과가 반환되지 않고, 누락 윤달을 평달로 채우지 않으며, 독립 대조 미실행이 명시된다.

### S1-B: 시간대·절기

실제 tzdb 로딩을 고정하고 현지시각의 gap/fold·미상 구간을 처리한다. Skyfield/JPL은 배치에서만 사용하고 실제 kernel 범위를 검증한다. KASI 표시 시계와 출생 당시 시계를 따로 정규화한다.

**핵심 완료 증거:** 같은 zone 데이터가 다른 환경에서도 사용되고, 24:00·연도 경계·절기 인덱스·반올림이 독립 fixture와 맞는다. 소수 표본 일치가 전기간 통과로 표시되지 않는다.

### S1-C: 배포·검증 승인

권리 검토, 원천 완결성, 독립 대조, 정규화 결과 재현성을 묶어 배포본을 만든다. 미승인 배포본이 운영 경로에 들어오지 못하게 한다.

**핵심 완료 증거:** 손상 파일·누락 절기·버전 혼합·미승인 데이터가 모두 차단되며, 네트워크를 막아도 승인 자료의 조회가 가능하다.

위 구분은 구현 순서의 범주다. 정확한 파일 경로·테스트·명령·커밋 단위는 S1 상세 설계 검토 후 별도의 구현 계획에서 정한다.

## 4. 후속 계산 규칙에서 숨기지 않을 선택

S2에서는 입춘/12절 기준, 일주 기준일, 00시/23시/야자시, 시주 천간에 쓰는 일간, 법정시/표준시/태양시를 명명된 `ruleset_id`로 관리한다. 현재 자료만으로 어느 관례가 보편적 정답이라고 확정하지 않는다.

시간을 모르면 정오로 채우지 않고 가능한 구간에서 공통인 결과와 달라지는 결과를 나눈다. 윤달 미상도 같은 원칙으로 처리한다. 근거 없는 후보 확률을 붙이지 않는다.

S6의 대운 방향 정책에 필요한 입력은 정책에 맞게 명시적으로 받으며 파트너 유형이나 성적 지향에서 추정하지 않는다. 궁합 점수·감정 지수는 산식과 의미를 정의하기 전에는 임의 값으로 채우지 않는다.

## 5. 검증 결과 표기 규칙

| 표시 | 뜻 |
|---|---|
| 문서 확인 | 공식 설명을 읽음. 실행을 뜻하지 않음 |
| 자기 일관성 통과 | 왕복/불변식 검증. 독립 원천 대조와 다름 |
| 독립 기준 대조 | 확인된 별도 근거와 일치/차이를 비교 |
| 규칙 구현 통과 | 승인된 관례를 코드가 재현함. 미래 예측력과 다름 |
| 출시 승인 | 정의한 지원범위·권리·운영 조건까지 검토 완료 |

테스트 수·커버리지·정확도라는 한 숫자로 위 다섯 상태를 합치지 않는다. 외부 자료 미확보 시험은 `skipped` 또는 `blocked`로 기록하고, 해당 증거가 필수인 배포 승격은 차단한다.

## 6. 작업 전달 원칙

제품 코드는 작업 브랜치와 PR로 전달하고, 관련 설계·테스트 명령·실제 결과·남은 제한을 함께 기록한다. 자동 병합·운영 배포는 별도 실행으로 구분한다. 작성된 PR이나 문서만으로 테스트 실행·배포 성공을 주장하지 않는다.

현재 보관된 연구 표본은 초기 회귀 자료 후보다. 환경·버전·원천 해시를 재현하고 독립성 수준을 확인한 뒤 테스트 자료로 승격한다. 기존 JSON의 결과를 검증 없이 통과 상태로 복사하지 않는다.
