# 공식 원천 검증 구현과 발견된 수치 차이

기록일: 2026-10-21. 코드 기준: `f26492be015d54df59eb0c9d6e7bc8cb88d2ff34`.

**구현 테스트는 통과했지만, 공식 절기 전기간 수치 대조는 실패했습니다. 운영 배포·데이터 승인을 하지 않습니다.**

## 이번 범위

PR #3 위에서 기존 S1의 공식 원천 검증 공백을 채웠습니다. Express 메인 API, Python 계산의 단일 기준, PostgreSQL 연결 구조는 변경하지 않았습니다. 원국·대운·용신·개인 데이터 저장·사용자 인증을 추가했다고 주장하지 않습니다. 상용 운세 API는 사용하지 않았습니다.

- `sazu.kasi_reference`: 공식 TXT 전체 문서의 해시/크기, 헤더의 시계/정밀도/코드, 인코딩, 날짜·24:00, 연도별 누락/중복/순서를 검사합니다. 비교할 구간 밖의 손상도 거절합니다.
- `sazu.term_audit`: 요청한 전체 키를 비교하고 모든 불일치의 연도·절기 ID·표시 분값 대비 차이를 기록합니다. 일부 교집합 일치나 빈 후보를 통과로 처리하지 않습니다.
- `sazu.source_audit`: 로컬 관리 명령으로만 동작합니다. HTTP에 파일 경로나 다운로드 기능을 노출하지 않습니다.
- `tools.audit_official_terms`: 고정된 공식 파일과 천문력 해시를 검증한 뒤 전체 대조 보고서를 생성합니다.
- `tools.diagnose_term_clocks`: 동일한 TT 사건에서 UTC와 별도의 UT1 표시 가설을 비교하는 연구 도구입니다. 운영 시각이나 합격 기준을 바꾸지 않습니다.

314개 모두 계산값이 공식 표시 분값보다 이릅니다. 1920–1959년257개, 1960–1971년26개, 1972–2025년19개, 2026–2050년12개입니다. 비교 기준은 `[표시값-30초, 표시값+30초)`입니다. 합격을 만들기 위해 이 범위를 넓히지 않았습니다.

**주의:** 분으로 반올림된 자료와의 차이는 초 단위 물리 오차를 뜻하지 않습니다. KASI 원문의 시계 표기는 고정 UTC+9입니다. 같은 천문력 계보일 가능성을 배제하지 못했으므로 물리적 원천의 완전한 독립성은 미확정입니다.

## 시간척도 진단 — 채택하지 않은 가설

Skyfield의 동일 TT 사건에 대해 내장 DUT1을 적용한 UT1 표시 가설을 따로 비교했습니다. 원천 값·허용오차·기존 운영 코드는 변경하지 않았습니다.

| 구간 | 총수 | 기존 UTC 일치 | UT1 표시 가설 일치 |
|---|---:|---:|---:|
| 1920–1971 | 1,248 | 965 | 1,239 |
| 1972–2025 | 1,296 | 1,277 | 1,280 |
| 2026–2050 | 600 | 588 | 582 |
| 합계 | 3,144 | 2,830 | 3,101 |

이 결과는 과거 시간척도 해석이 중요한 원인 후보라는 근거입니다. **KASI가 실제로 UT1을 사용한다는 확인은 아닙니다.** 미래 구간에서는 오히려 일치 수가 줄며 이 가설에서도43개 차이가 남습니다. 가설 출력은 운영 UTC 시각으로 반환하지 않고 `adopted=false`로 기록했습니다. 정확한 과거/미래 시간 모델과 잔여 차이는 후속 조사 대상입니다.

참고한 1차 문서: [Skyfield 시간척도](https://rhodesmill.org/skyfield/time.html), [시간 API](https://rhodesmill.org/skyfield/api-time.html), [KASI 원문](https://astro.kasi.re.kr/kor/almanac/solarTerms/download). 기술 문서의 일반 설명과 이 프로젝트의 진단 결과를 구분합니다.

## 테스트 증거

로컬 최종 `PYTHONPATH=src:. python -m pytest -q`: **323 passed, 1 skipped, 실패0**. 기존221개에102개를 추가했습니다. skip은 로컬 JPL kernel이 없는 기존 모델 통합시험입니다. 이번 실제 공식 대조는 원격에서 실제 파일을 사용해 별도로 실행했습니다.

Ruff/compileall, Node HTTP46개, strict TypeScript, 실제 Express↔Python 프로세스8개 테스트가 통과했습니다. [서비스 연결 CI](https://github.com/jskjw157/sazu/actions/runs/39562263057)도 성공했습니다. 테스트·관리 코드의 성공과 공식 수치 대조 실패를 하나의 녹색 숫자로 합치지 않습니다. 새로운 독립 코드 리뷰는 미실행이며 자체 검토와 테스트만 수행했습니다.

## 실행 방법

기존 개발/천문 의존성을 설치한 연구 환경에서만 실행합니다. 공식 파일의 이용조건을 검토하고 별도 수집 작업으로 확보한 다음 로컬 경로를 지정합니다. 런타임 서비스가 시작되면서 자동으로 다운로드하지 않습니다.

```bash
python tools/audit_official_terms.py \
  --kasi /operator-controlled/kasi.txt \
  --kernel /operator-controlled/de440s.bsp \
  --acquired-at '실제_취득_UTC_ISO8601' > official-audit.json
```

`--acquired-at`에는 실제 취득 UTC 시각을 넣습니다. 고정된 기대 파일 해시가 다르면 검토 없이 새 해시로 교체하지 않습니다. 종료코드0은 수치 대조 통과,1은 수치 불일치,2는 입력·자료 미확보/차단,3은 예기치 않은 오류입니다. 어느 종료코드도 상용 출시 승인과 동의어가 아닙니다.

범용 JSON stdin 관리 CLI는 `python -m sazu.source_audit inspect|compare`입니다. 요청은64KiB 이하이며 추가 필드·중복 JSON키·비유한 값·손상 파일을 거절합니다. `inspect`는 원문 전체 대신 메타데이터만 출력합니다. 신뢰된 부모 디렉터리에 있는 운영자 관리 파일을 사용해야 합니다.
