# 과거 UTC 변환 수정과 남은 원천 불일치

작성: 2026-10-21. 관련: [PR #6](https://github.com/jskjw157/sazu/pull/6), [이슈 #5](https://github.com/jskjw157/sazu/issues/5).

## 결론과 완료 범위

**확인된 과거 UTC 변환 버그를 수정했다. 기존 314개 불일치 중 실제 수치가 일치로 바뀐 것은 25개다. 이슈 전체 해결이나 출시 완료가 아니다.** 기존 257개 불일치가 있는 1960년 이전 구간은 시간척도 미확정으로 남았고, 1960년 이후에는 32개 불일치가 남는다. 원래 검사 대상 3,144개를 보고서에서 유지한다. 미확정 항목을 통과로 세거나, 허용오차를 늘리거나, 공식 원천을 수정하지 않았다.

실행 검증한 제품 코드: `a817a70f25fc1e5238e3157061bf394e5a5bcfbb`. 이 문서를 추가하는 커밋은 제품 코드를 바꾸지 않는다. Express 메인 서버/Python 계산 구조, 상용 사주 API 미사용, main 미병합, 운영 미배포 상태를 유지한다.

## 원인과 구현

이전 구현은 Skyfield의 `utc_datetime()` 출력을 모든 과거 날짜에 적용했다. 1960–1971년 UTC에는 현재의 정수 윤초표와 다른 주파수 드리프트가 있었다. SOFA에서 파생된 ERFA는 날짜 및 하루의 경과 비율을 사용한 해당 변환을 제공한다. [ERFA dat.c](https://raw.githubusercontent.com/liberfa/erfa/master/src/dat.c)의 설명과 수식을 근거로 `PyERFA==2.0.1.5`를 고정해 사용했다. 사후 KASI 적합용 보정상수를 만들지 않았다.

- `src/sazu/clock_projection.py`: 두 부분 TT 날짜를 TAI, UTC 순서로 변환하는 `sofa-utc-v2` 정책.
- 실제 ERFA 바이너리, 윤초표, 패키지 버전과 시간 정책을 모델 식별자에 기록.
- 1960년 이전: TT 사건은 유지하되 `instant_utc=null`, `utc_undefined_before_1960`. UT1을 UTC라고 바꾸어 쓰지 않는다. 역사적 민간시각과 원천의 소급 표기 관례는 추가 확인 대상이다.
- 윤초 `23:59:60`은 별도 문자열/상태로 유지하며 Python datetime으로 잘못 변환하지 않는다.
- 미래: [IERS Bulletin C72](https://datacenter.iers.org/data/html/bulletinc-072.html)의 2026년 말 윤초 없음 공지를 확인 근거로 고정했다. 2027년 이후 UTC 표시는 현재 표를 유지한 조건부 가정으로 명시한다. 실행 날짜나 OS 설정으로 이 범위를 자동 연장하지 않는다.
- `legacy-skyfield-v1`은 과거 결과 재현용으로만 남긴다. 과거 UTC 정확성이나 운영 승인 근거로 쓰지 않는다.

천문 TT 사건, 태양 황경 산식, DE440s, KASI 원문과 분 반올림 판정구간은 변경하지 않았다. 실제 전기간 재실행에서 **구·신 모델의 TT 사건 digest가 동일**했다.

## 실제 재대조 결과

[clock-revision CI 39583136603](https://github.com/jskjw157/sazu/actions/runs/39583136603), [보고서 아티팩트](https://github.com/jskjw157/sazu/actions/runs/39583136603/artifacts/12338306822).

| 구간 | 전체 절기 | 수정 전 일치 | 수정 후 일치 | 수정 후 수치 불일치 | 시간척도 미확정 |
|---|---:|---:|---:|---:|---:|
| 1920–1959 | 960 | 703 | 0 | 0 | 960 |
| 1960–1971 | 288 | 262 | 287 | 1 | 0 |
| 1972–2026 | 1,320 | 1,301 | 1,301 | 19 | 0 |
| 2027–2050 | 576 | 564 | 564 | 12 | 0 |
| 전체 | 3,144 | 2,830 | 2,152 | 32 | 960 |

첫 행의 0은 정확도 하락이나 960건 오류를 뜻하지 않는다. UTC가 정의되지 않은 구간에 대해 종전의 소급 UTC 일치를 유효한 UTC 검증으로 취급하지 않는 것이다. 원래 불일치 314개는 **수정 25 + 과거 시간척도 미해결 257 + 잔여 수치 불일치 32**로 나뉜다. 따라서 “314→32, 282건 해결”이라고 보고하면 틀리다.

남은 32건은 공식 표시 분값보다 30.016547~32.385599초 앞선다. 이는 반올림 구간의 하한보다 약 0.0165~2.3856초 앞선다는 뜻이며, 물리적 참값에 대한 오차를 측정한 것이 아니다. 미래 576개는 현재 윤초표 가정하의 수치 비교이고 실현될 UTC를 보장하지 않는다.

전체 수치 게이트는 여전히 `failed`, `production_authorized=false`다. 미정 시간척도를 거절한 것만으로 이슈 #5를 닫지 않는다.

## 추가 발견: 같은 기관의 자료도 판본에 따라 달라짐

[KASI 달력자료](https://astro.kasi.re.kr/life/post/calendardata)의 2024년 항목(자료생성 2023-04-25)은 소설을 **2024-11-22 04:56**으로 표기한다. 이번에 고정한 2026-09-01 장기 TXT는 **04:57**이다. 모델 출력은 **04:56:29.763188, 고정 UTC+9 표기**로 04:56에 반올림된다.

단, 해당 연도별 웹자료는 스스로 **공식 발표 전 자료**라고 안내한다. 이 차이는 판본·계산 기준을 확인할 필요가 있다는 근거이지, 장기 TXT의 오류나 우리 모델의 절대적 정답을 증명하지 않는다. 이 자료를 더 잘 맞는 정답으로 바꿔 끼우지 않았으며, 나머지 31건을 같은 원인이라고 추정하지 않았다.

## 검증 증거

- 원격 전체 Python 시험: **355 passed, 1 skipped, 0 failed**, 4.56초. `regression` job `119165377652`. 32개 테스트 추가. skip은 해당 작업에 로컬 JPL kernel이 없던 기존 모델 회귀시험이며, 수치 대조 작업에서는 실제 JPL 파일을 별도로 사용했다.
- Ruff와 compileall: 동일 원격 작업 통과.
- [service-boundary 39583287506](https://github.com/jskjw157/sazu/actions/runs/39583287506): `unit-and-process`, `compose-integration` 모두 success. TypeScript/Node/실제 프로세스 연결/실제 Docker·PostgreSQL/포트 격리/의존성 중단 시험 재실행 성공.
- 독립 날짜 기준: 1961·1965년 TAI-UTC, 하루 내 드리프트, 1972·2017 UTC, 실제 윤초, 미래 가정, 비정상 입력, OS 시간대 독립성.
- 실제로 실패 테스트를 관측한 뒤 구현했다. 로컬 전체 subprocess 시험은 실행 제한으로 완료하지 못했으나, 이후 원격 전체 시험에서 위 355개 통과를 확인했다. 로컬 완료로 바꾸어 기록하지 않는다.
- 새로운 독립 코드 리뷰는 실행하지 못했다. 자체 검토와 실제 테스트 증거만 기록한다.

## 호환성 및 아직 남은 일

`SolarTermEvent.instant_utc`는 이제 null일 수 있다. 연구용 생성 결과를 소비하는 코드는 `utc_projection.status`와 TT를 확인해야 한다. 비교 보고서 schema는 2이며 `unresolved_clock_keys`, `provisional_clock_keys`, `numerically_compared`를 제공한다. 기존 Express 달력/시각 HTTP 입력·출력은 변경하지 않았다. 아직 운영용 절기 API가 출시된 상태는 아니다.

잔여 승인 조건은 (1) 1960년 이전 원천의 실제 시간척도와 역사적 민간시각 연결, (2) 남은 32건의 판본·천문 모델·반올림 기준 설명, (3) 공식 음양력 전기간 대조, (4) 원천 이용권과 신뢰된 release 활성화다. 원천 다운로드 성공과 수치 비교 성공, 상용 이용권, 배포 승인을 서로 별도로 유지한다.
