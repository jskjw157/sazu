# SAZU 자체 원천·시간 기반 설계

작성일: 2026-10-21  
분류: 신규 기반 시스템의 아키텍처 설계  
문서 상태: **상세 설계 검토안 — 코드 미구현, 운영 배포 미승인**  
상위 결정: [ADR-0001](../../decisions/0001-no-commercial-fortune-api.md)

## 1. 목적과 확정 범위

한국어 AI 연애·운세 앱이 상용 운세 API 없이 계산할 수 있도록, 한국 달력·절기·출생시각의 **재현 가능한 입력 기반**을 만든다. 속도 위주의 데모보다 원천 추적, 경계 정확성, 불확실성 표현, 변경 검증을 우선한다.

사용자가 확정한 것은 상용 운세 API 미사용, 개발공수보다 완성도 우선, 검토한 오픈소스 활용이다. 아래의 모듈 경계·지원 목표·시험 기준은 그 방향을 구현하기 위한 새 상세 설계안이다. 포괄적 동의를 구체적인 명리 관례나 아직 없는 코드의 승인으로 간주하지 않는다.

이번 하위 시스템 S1의 산출물은 `SourceManifest`, `CalendarDate`, `SolarTermEvent`, `NormalizedBirth`, `DatasetRelease` 계약과 이를 만드는 도구다. 완성된 팔자·대운·궁합·캐릭터 채팅을 S1의 결과라고 부르지 않는다. 계산 규칙 엔진은 이 계약을 소비하는 S2로 분리한다.

## 2. 현재 증거와 보존 원칙

기준 커밋 `60bdd8f01a1889f586dc5b39b6c46a59c9fbef5c`에는 문서·JSON·XLSX 등 11개 자료만 있다. 제품 코드, lockfile, migration, 실행 CI는 없다.

- [원천 조사](../../research/saju_source_commercial_research_20261020.md)는 공식 한국 달력 + 천문 계산 + 자체 규칙을 추천한다.
- [기존 검증 기록](../../../data/verification/saju_source_verification_20261020.json)은 1993·2026년 48개 절기와 일부 라이브러리 경계의 연구 표본이다. 이번 문서 작성에서 재실행한 결과가 아니다.
- [기존 DB 구축안](../../architecture/saju_db_blueprint.md)과 [예시](../../../data/examples/saju_db_examples.json)는 제안·초안이다. 승인된 규칙·원고나 실제 운영 DB가 아니다.

기존 보고서의 가격·공급자 평가는 역사 기록으로 보존하되 현재 개발 의존성에서 제외한다. 기존 증거의 결과에 맞추려고 기대값을 자동 덮어쓰지 않는다.

## 3. 접근법 비교와 권장 구성

| 접근 | 장점 | 현재 선택 |
|---|---|---|
| 완성형 만세력 라이브러리 하나로 전체 계산 | 연결이 간단함 | 한국/중국 역법, 시계, 자시 관례가 한 덩어리로 숨을 수 있어 채택하지 않음 |
| Python 원천·계산 핵심 + 얇은 서비스/클라이언트 | 천문 라이브러리 재사용, 규칙 구현 한 곳, 시험 격리 | **권장 설계** |
| Python 배치 + TypeScript에 별도 전체 계산 구현 | 프론트 기술과 가까움 | 표 조회에는 적절하나 동일 규칙 이중 구현은 초기부터 두지 않음 |

S1은 Python 라이브러리와 배치/검증 CLI로 설계한다. S2도 같은 핵심 계약을 사용한다. 향후 HTTP 계층은 FastAPI/Pydantic 후보로 만들고, TypeScript 앱은 생성된 계약을 소비한다. 우리 서버에 자체 API를 두는 것은 상용 운세 API 사용이 아니다. 새 프레임워크·특정 버전 설치는 구현 계획에서 실제 호환성을 확인한 뒤 수행한다.

초기 운영 구조는 모듈식 단일 서비스 + PostgreSQL이다. Kubernetes, 메시지 브로커, 별도 벡터 DB, 다중 계산 언어를 완성도의 대용물로 추가하지 않는다. 무거운 천문 검색은 배치에서 수행하고 요청 경로에서는 검증된 테이블만 조회한다.

## 4. 오픈소스 재사용과 직접 구현의 경계

| 구성 | 재사용 대상 | 우리 책임 |
|---|---|---|
| 한국 음양력 | usingsky/korean_lunar_calendar | 새 인스턴스/요청 격리, 엄격한 유효성 검사, 윤달, 실패 시 이전 결과 차단, 독립 대조 |
| 절기 계산 | Skyfield + JPL kernel | 데이터 획득/해시/범위 검사, 황경-절기 매핑, 시간 모델·정밀도 기록, 배포본 생성 |
| 역사적 시간대 | Python zoneinfo + 고정 tzdata | 실제 파일 로딩 고정, gap/fold 검출, 시간 미상 구간, tzdb 한계 표시 |
| 자동 시험 | pytest + Hypothesis 후보 | 도메인 불변식·독립 기대값·변경 영향·재현 로그 |
| 의존성 관리 | uv 후보 | 버전/플랫폼 lock 검증, 원천 바이너리 별도 manifest, 오프라인 실행 검증 |
| 추가 비교 | Astronomy Engine, 필요시 6tail/sxtwl | 운영 의존성에서 분리, 원천 계보/관례 차이 분류 |

상용 공급자 SDK, 사주 API 클라이언트, 그 자격증명이나 장애 대체 코드는 만들지 않는다. 검토했던 결함이 있는 만세력 패키지를 편의상 운영에 연결하지 않는다. 오픈소스가 유명하거나 MIT라는 이유만으로 정확성·내장 데이터 권리를 승인하지 않는다.

과거 기록의 Skyfield 1.55·DE440s·usingsky commit은 **재현할 기준 후보**다. 새 환경에서 해당 아티팩트의 존재·해시·의존성·결과를 재확인한 뒤 lock한다. 부합하지 않으면 불일치를 기록하고 새 비교 배포본을 만든다. 이전 숫자를 맞추기 위해 검증 결과를 수정하지 않는다.

## 5. 지원 범위와 정밀도

S1의 첫 완전 대조 목표는 정규화된 양력 `1920-01-01`~`2050-12-31`이다. 이는 출시 보장 범위가 아니다. 연초 이전 절입/연말 이후 절입 조회용으로 `1919`~`2051`의 절기 보조 구간을 생성한다. 음양력 서비스 입력의 유효범위는 정규화 결과 날짜로 검사하며, 보조 절기 연도가 음력 변환 지원연도 확대를 뜻하지 않는다.

첫 공개 보장 대상은 한국 달력·`Asia/Seoul`에 대해 증거가 확보된 구간이다. 시간대 코드는 IANA zone을 처리하도록 설계하되, 해외 사례 시험이 전체 국가·기간 지원을 뜻하지 않는다. 지원 행렬은 달력/날짜/zone/정밀도/정책/자료 버전의 교집합으로 관리한다. 과거 시간대 추정·근거 부족 구간은 경고·후보 또는 미지원으로 처리하며 조용히 현재 UTC+9를 넣지 않는다.

수집 목표, 라이브러리 수치 지원범위, 검증 범위, 실제 서비스 지원범위, 가입 연령 조건은 각각 다른 필드다. 범위의 내부 누락도 검사한다.

## 6. 원천 획득과 라이선스

`등록 → 획득 → 파싱 → 검증 후보 → 승인 배포본` 단계와 `이용권 검토 상태`를 분리한다.

- 공식 API는 문서 확인만으로 성공 호출로 표시하지 않는다. KASI 키는 필요한 시점의 비밀 저장소에서 제공하며 URL·manifest·로그에 기록하지 않는다.
- KASI TXT의 직접 상용 적재/재배포 권한이 미확정이면 공개 Git·배포물에 원문 전체를 넣지 않는다. 접근 가능성과 이용권은 별개다.
- JPL/NAIF kernel은 해당 파일의 출처·조건을 별도 기록한다. 라이브러리의 MIT를 kernel 라이선스로 쓰지 않는다.
- 원천 수집기는 공식 호스트 허용 목록, 제한된 리다이렉트, timeout, 파일 크기 한도, 재시도 상한, 스트리밍 해시 및 원자적 저장을 가진다. 손상·부분 파일을 최종 경로로 승격하지 않는다.
- 로컬 검증에 원천 파일이 없으면 `SOURCE_NOT_AVAILABLE`을 반환한다. 상용 API나 임의 날짜 테이블로 대체하지 않는다.
- 배치 수집과 런타임은 프로세스·자격증명·네트워크 권한을 분리한다. 런타임 시작 시 다운로드가 발생하는 라이브러리 경로를 사용하지 않는다.

각 `SourceManifest`는 source ID, 제공자, 공식 URL, 취득 UTC 시각, 원본 SHA-256, 자료/코드 버전, 크기·형식, 지원범위, 시계·정밀도, 이용조건 URL/검토 상태, 원천 계보, 파서 버전을 가진다. SHA-256은 무결성 식별이지 제공자 인증이나 이용허락의 증명이 아니다.

## 7. 모듈 계약

다음 파일/모듈은 **구현 시 제안 구조**이며 현재 존재하는 코드가 아니다.

| 모듈 | 입력 | 출력/책임 | 금지된 의존성 |
|---|---|---|---|
| `sources` | 로컬 파일 또는 승인 획득 요청 | 원문/manifest/획득 오류 | 사용자 프로필 |
| `calendar` | 달력 종류·연월일·윤달 상태 | 가능한 양력 날짜, 역변환, 검증 trace | LLM, 상용 API |
| `solar_terms` | 고정 kernel·timescale·연도 | 24개 절기 사건과 provenance | 출생정보, 런타임 자동 다운로드 |
| `temporal` | 현지 날짜·시간 범위·zone·fold | 정규화 UTC 구간들의 합집합 | 현 위치 자동 추정, 임의 noon |
| `datasets` | 자료·검증·이용권 근거 | 검증 가능한 불변 배포본/지원 행렬 | 미검증 자료 자동 승인 |
| `validation` | 후보 결과 + 별도 근거 | 사례별 비교·미실행·오류·차이 분류 | 기대값 자동 생성 후 독립 정답 주장 |

시간 비교와 단순 날짜 변환은 순수 로직으로 격리한다. `source_registry`/manifest 조회는 어댑터로 주입한다. 후속 HTTP·DB·LLM은 핵심 계산에 역으로 들어오지 않는다.

## 8. 한국 달력 어댑터

달력 선택값은 `gregorian` 또는 `korean_lunar`이며 추측하지 않는다. 음력 윤달은 `regular / leap / unknown`의 명시적 상태다.

- 잘못된 날짜는 다른 날짜로 보정하지 않는다. 불리언·실수 등을 정수 연월일로 묵시 변환하지 않는다.
- 라이브러리 setter의 성공 여부를 확인한 뒤 결과를 읽는다. 매 요청은 격리된 상태를 사용한다.
- `leap=unknown`은 해당 연·월에 실제 가능한 평달/윤달 날짜만 각각 검사해 후보를 반환한다. 한 날짜만 유효하면 그 후보를 반환하되 원본의 미상 상태를 보존한다.
- 달력의 월간지·연간지를 절입 기반 월주·입춘 연주로 이름만 바꿔 반환하지 않는다.
- 왕복 시험은 자기 일관성 검증이다. 공식 값 대조의 대체가 아니다.

S1은 해외 출생자의 한국 음력 날짜 의미를 자동 해석하지 않는다. 향후 지원 시 `출생지의 현지 날짜에 대한 한국 음력 표기`인지 별도 선택/명세로 추가한다. 지원 전에는 `UNSUPPORTED_CALENDAR_LOCATION_COMBINATION`으로 거절한다.

## 9. 절기 생성·정규화

태양의 겉보기 지심 황경과 사용하는 좌표계/분점 정의를 고정한다. Skyfield 공식 solar terms 연산의 버전과 설정을 기록하고 라이브러리 인덱스를 그대로 한국 절기 ID로 사용하지 않는다.

`SolarTermEvent` 계약:

- 황경을 포함한 안정된 term key, 한글 이름, KASI ID와의 명시적 매핑.
- TT 수치 표현과 계산 시각 UTC, 원문 표시 시각·시계·정밀도, 변환 모델 ID.
- kernel/라이브러리/timescale/파서/매핑 버전과 원천 manifest ID.
- 수치 탐색 허용 오차와 물리적 불확실성의 분리. 근거 없는 물리 오차 상한은 `unknown`.
- 검증 상태와 반올림 기준값의 비교 결과.

연도별 24개와 시간 순서·중복을 확인한다. 검색 구간은 고정 UTC+9의 해당 연도 시작/끝을 UTC로 옮긴 반개구간으로 정의하며 경계 중복을 제거한다. 12절의 월 전환 매핑은 황경 `315 + 30*k`의 360도 나머지와 명시적 표를 대조한다. 전체 24기를 월 경계로 사용하지 않는다.

KASI TXT의 고정 UTC+9는 역사적 `Asia/Seoul`과 구분한다. `24:00`은 원문을 보존하고 다음날 00:00으로 별도 정규화한다. 반올림 규칙이 확인된 분값과 후보 계산값을 비교할 때는 반올림 셀에 포함되는지를 검사한다. 분 일치율을 물리 오차나 사주 정확도로 부르지 않는다.

계산 시각은 해당 모델 안의 결정론적 경계다. 숫자가 마이크로초까지 있어도 참값의 마이크로초 정확도를 보장하지 않는다. 과거 UTC 이전 시기와 미래 윤초/지구자전 가정은 사용한 시간 모델의 해석으로 기록한다. 모델 변경은 새 배포본이며 과거 결과를 덮어쓰지 않는다.

## 10. 출생시각과 불확실성

`NormalizedBirth`는 한 시각 대신 **날짜 후보별 UTC 구간들의 합집합**을 표현할 수 있어야 한다. 무작위 표본이나 매시간 한 번 계산으로 경계 가능성을 놓치지 않는다.

입력 시간의 의미:

| 모드 | 의미 |
|---|---|
| `instant` | 명시적으로 주어진 시각 점. 측정 정확도를 보증하지 않음 |
| `minute_bucket` | 해당 분 시작 이상, 다음 분 시작 미만 |
| `rounded_minute` | 사용자가 분 반올림이라고 명시한 경우에만 그 반올림 구간 |
| `interval` | 사용자가 제공한 시작/끝 및 포함 규칙 |
| `unknown` | 해당 현지 날짜의 실제 존재하는 전체 시간 구간 |

기존 예시의 `exact_minute`를 위 모드로 조용히 변환하지 않는다. 입력 계약의 migration과 화면 안내를 함께 정한다. 정밀도가 누락되면 검증 오류다.

고정 tzdb 파일을 읽도록 `PYTHONTZPATH`/직접 파일 로딩 정책을 고정하고 실제 사용한 zone 파일 해시를 기록한다. Python zoneinfo는 기본적으로 OS 자료를 우선하므로 설치한 tzdata 버전 기록만으로 재현성을 주장하지 않는다. [E03]

점 시각은 fold 0/1을 각각 UTC로 보낸 뒤 원래 현지값으로 왕복해 유효한 후보를 판별한다. 0개이면 `NONEXISTENT_LOCAL_TIME`, 2개이면 명시적 선택 또는 복수 후보다. 겹치는 시각을 첫 후보로 몰래 선택하지 않는다. 시간 구간은 offset 전환으로 분할해 실제 존재하는 구간만 보존하며, 전체 현지 날짜가 존재하지 않으면 오류다.

윤초 `:60` 입력은 기본 datetime이 표현하지 못하는 값으로 명시 거절한다. 지원을 추가할 때는 별도 시간 표현과 테스트를 사용한다. 현재 위치·접속 시간대를 출생지 대신 쓰지 않는다.

S1은 진태양시를 임의로 기본 적용하지 않는다. 실제 UTC instant와 후속 일·시주 계산용 보정시각을 분리한다. S2에서 법정시/표준시/경도시/진태양시 정책을 식별자로 정의하고, 필수 위치나 보정 자료가 없으면 해당 정책을 거절한다. 대한민국 출생에 일률적으로 30분을 빼는 것으로 대체하지 않는다.

## 11. 배포본·저장·장애 처리

`DatasetRelease`는 calendar coverage, solar-term coverage, 검증된 zone/기간, 허용 입력 정밀도, 포함 manifest, 검증 보고 ID, rights review, schema version을 고정한다. 배포본 활성화 계정과 운영 읽기 계정을 분리한다. 임의의 `approved=true` JSON 업로드만으로 운영 데이터가 되는 경로를 만들지 않는다.

PostgreSQL에는 기존 설계처럼 `(release_id, solar_date)`와 `(release_id, event_year, term_key)`를 복합키로 사용한다. 음력 역조회 고유키에는 윤달을 포함한다. 여러 버전의 값이 한 조회에서 섞이지 않도록 요청 시작 시 배포본을 고정한다. 긴 원문은 제한된 파일 저장소에 두고 DB는 위치·해시를 가진다.

조회 범위 누락, 손상된 manifest, 원천 간 충돌, 미승인 배포본은 성공이 아니다. 오류는 `INVALID_INPUT`, `UNSUPPORTED_RANGE`, `NONEXISTENT_LOCAL_TIME`, `SOURCE_NOT_AVAILABLE`, `DATA_INTEGRITY_FAILED`, `RELEASE_NOT_APPROVED`, `SOURCE_CONFLICT` 등 안정된 코드와 재시도 가능 여부를 반환한다. 오류 메시지에 생년월일·키·원문 URL 쿼리를 포함하지 않는다.

S1 CLI의 개인 출생 입력은 기본적으로 저장하지 않는다. 배치 산출물에는 실제 사용자 입력을 넣지 않는다. 향후 개인별 캐시를 만들면 사용자 격리와 삭제를 적용하며, 생년월일의 단순 해시를 익명화라고 부르지 않는다.

## 12. 검증 체계와 통과 조건

TDD로 실패를 먼저 재현하고 최소 구현 후 구조를 정리한다. 도메인 정확성, 회귀 안정성, 보안 시험은 분리 집계한다. 공식 API가 필요한 검증이 미실행이면 CI가 녹색이라는 이유만으로 출시 승인하지 않는다.

| 게이트 | 요구 증거 | 실패/미실행 처리 |
|---|---|---|
| G1 원천 무결성·권리 | 파일 해시·범위·라이선스 검토·누락/중복 검사 | 배포 승격 차단 |
| G2 한국 달력 | 목표기간 전 날짜 왕복 + 독립 공식 값 전수 대조 | 미대조 구간은 검증 범위에서 제외; 불일치 행 전수 기록 |
| G3 절기 | 목표/보조 구간 구조 검사, 공식 중첩 구간 전수 대조, 차이 원인 분류 | 기존 표본 일치를 전체 통과로 승격하지 않음 |
| G4 시간대 | 실제 고정 데이터 확인, 한국 과거 offset/DST, 해외 gap/fold/날짜 건너뜀 fixture | 해당 조합 미지원 또는 명시적 오류 |
| G5 결정론 | 깨끗한 환경 두 번 생성·정규화 결과 동일, 시드/버전/파일 해시 보존 | 재현 실패 원인 해결 전 배포 차단 |
| G6 방어·운영 | 네트워크 차단 런타임, 손상·부재·부분 다운로드, 버전 혼합·실패·복구 | 잘못된 성공 응답 0건 |

독립 공식 값이 없으면 새로운 검증 원천을 확보할 때까지 근거 부족으로 남긴다. 같은 테이블을 사용하는 포트끼리의 일치, 자신의 출력으로 만든 기대값, API 공급자의 홍보문구를 독립 기준에 합산하지 않는다.

Hypothesis는 윤달 여부·범위·정밀도·offset 전환·반올림 조합을 생성하고 실패 사례를 축소/보존하는 용도로 사용한다. 무작위 시험은 유한한 전체 날짜 대조를 대신하지 않는다. 중요 오류 주입은 실패 setter의 stale result, 누락 윤달, 24:00 처리, OS tzdb 혼입, 경계 포함 비교, 빈 후보의 참 처리, 해시 누락을 포함한다.

커버리지는 빠진 경로를 찾는 보조 지표다. 숫자를 채우려고 의미 없는 테스트를 늘리지 않는다. 각 안전 경계의 실패/성공 동작과 실제 오류 주입을 잡는 시험을 필수로 한다. 시간·메모리·파일 크기와 OS/Python/platform 정보를 기록하되 측정하지 않은 성능 목표를 달성했다고 쓰지 않는다.

## 13. 의존성·CI·변경 관리

구현 단계에서 Python minor, uv, 전이 의존성, wheel/source 해시, kernel, timescale, tzdb를 고정한다. CI는 lock 불일치를 자동 수정하지 않고 실패시킨다. `uv --locked` 동작과 frozen의 차이는 공식 문서대로 사용한다. [E06]

PR은 단위·속성·계약·로컬 fixture·오프라인 검증을 수행한다. 전체 기간의 비용 큰 독립 대조는 별도 데이터 검증 실행으로 두되, 해당 결과 없이 배포 승격할 수 없게 연결한다. 의존성 자동 갱신은 별도 PR + 기존/후보 차이 보고를 요구한다. 네트워크 허용 수집 작업은 테스트/서비스 계정과 분리하며 공급자 장애를 정상 결과로 기록하지 않는다.

오픈소스 목록/SBOM, 라이선스 고지, 취약점 검사, secret scan, 낮은 권한의 CI와 빌드 산출물 무결성 검사를 운영 준비 단계에 연결한다. 실제 사용자 파일·인증키·권한 미확정 원문은 공개 저장소에 넣지 않는다.

## 14. 승인 경계와 다음 산출물

이 문서로 상세 설계 검토를 먼저 한다. 그다음 S1의 파일별 구현 계획, 실패 테스트, 실행 방식이 정해져야 제품 코드 작업으로 넘어간다. 이번 문서에 적힌 인터페이스·시험표는 테스트 실행 결과가 아니다.

명리의 00시/23시/야자시·대운 관례는 S2의 별도 규칙 설계에서 명명한다. S1을 만들기 위해 이를 몰래 선택하지 않는다. 해석·계정·결제·모바일 UI의 상세 설계도 본 문서의 승인을 자동으로 공유하지 않는다.

전체 후속 하위 시스템과 완료 증거는 [QUALITY_ROADMAP.md](../../QUALITY_ROADMAP.md)에 연결한다. 달력/절기/시간대 중 미확정 항목이 있으면 구현 가능한 어댑터·검증기 작업은 계속하되, 검증되지 않은 계산 결과의 운영 공개는 막는다.
